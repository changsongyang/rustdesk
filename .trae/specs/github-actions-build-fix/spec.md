# GitHub Actions 构建打包与测试修复计划

## 为什么需要此规格文档

当前 GitHub Actions CI/CD 工作流存在多个构建错误和兼容性问题，需要系统性修复以确保：
- 构建过程稳定可靠
- 符合项目代码规范
- 不破坏现有功能
- 保持 Rust 版本不变

## 主要变更内容

### 1. 合规性修复
- 修复所有 Rust 编译错误
- 修复 FFmpeg 7.x API 兼容性问题
- 修复 hwcodec 库链接错误
- 修复 Rust 代码中的 mut 借用错误

### 2. 工作流兼容性优化
- 分析 GitHub Actions 工作流配置文件
- 优化步骤顺序和依赖关系
- 确保跨平台构建兼容性（Windows、macOS、Linux、Android）
- 修复库依赖链接问题

### 3. Rust 版本控制
- **严格维持当前使用的 Rust 版本（1.81）**
- 不进行任何 Rust 版本升级操作
- 确保所有依赖与当前 Rust 版本兼容

### 4. 性能稳定性保障
- 确保构建时间不超过修复前的 110%
- 优化不必要的构建步骤
- 保留有效的缓存机制

## 影响范围

### 受影响的规格
- Android 应用构建流程
- 跨平台桌面应用构建流程
- hwcodec 硬件编解码支持

### 受影响的代码
- `.github/workflows/` 工作流配置文件
- `libs/scrap/build.rs` 构建脚本
- `hwcodec` 依赖库（通过 patch 配置）
- `src/flutter_ffi.rs` Rust FFI 接口
- `src/tray.rs` 系统托盘功能

## 新增需求

### 需求：自动化构建错误检测与修复
系统应能够：
- 在每次提交时自动运行构建测试
- 识别并报告构建错误
- 提供清晰的错误信息帮助开发者定位问题

#### 场景：构建失败检测
- **当** 工作流执行 `cargo build` 命令时发生错误
- **那么** 工作流应失败并显示详细的错误信息和日志链接

#### 场景：构建成功验证
- **当** 工作流完成所有平台的构建
- **那么** 应生成构建产物并上传到 Artifacts

### 需求：跨平台构建兼容性
系统应确保：
- Windows (x86_64, i686) 构建成功
- macOS (x86_64, aarch64) 构建成功
- Linux (x86_64, aarch64) 构建成功
- Android (armv7, aarch64, x86_64) 构建成功

#### 场景：跨平台构建验证
- **当** 工作流在不同平台执行构建命令时
- **那么** 每个平台都应成功完成构建并生成对应的产物

### 需求：依赖版本稳定性
系统应确保：
- 所有 Cargo 依赖版本保持不变
- FFmpeg 库配置保持兼容
- hwcodec 通过 patch 指向正确的 fork 仓库

#### 场景：依赖版本锁定验证
- **当** 工作流解析 `Cargo.toml` 和 `Cargo.lock` 时
- **那么** 所有依赖版本应与锁定文件一致

### 需求：构建性能监控
系统应：
- 记录每个步骤的执行时间
- 在性能下降超过 10% 时发出警告
- 保持合理的缓存策略

#### 场景：性能监控与告警
- **当** 构建步骤执行时间超过历史平均时间 110% 时
- **那么** 应在日志中输出性能警告

## 修改的需求

### 需求：scrap/build.rs 库链接策略
**原始需求**：使用 vcpkg 管理 FFmpeg 依赖
**修改为**：根据平台动态配置 FFmpeg 库链接
- Windows：使用 vcpkg 安装的静态库
- macOS/Linux：依赖系统 FFmpeg 或动态加载
- Android：不链接 FFmpeg 静态库

### 需求：hwcodec 依赖管理
**原始需求**：直接链接 FFmpeg 静态库
**修改为**：不直接链接 FFmpeg 静态库，由 rustdesk 项目处理链接

## 移除的需求

### 需求：hwcodec 中的 vdpau 硬编码链接
**原因**：VDPAU 是可选的硬件加速功能，不应在所有 Linux 构建中强制链接
**迁移方案**：
- 将 vdpau 支持作为运行时检测功能
- 不在 build.rs 中硬编码链接
- 通过 FFmpeg 运行时动态加载

## 验证标准

1. **无错误构建**：所有平台的构建应成功完成，退出码为 0
2. **测试通过率 100%**：所有单元测试和集成测试应通过
3. **构建时间限制**：总构建时间不超过修复前的 110%
4. **产物完整性**：每个平台都应生成对应的构建产物
5. **日志可读性**：构建日志应包含清晰的错误信息和调试数据
